# モード、配信面、ルーティング

## 本文モード

### `consideration`

一つの問いや設計課題を、前提・主張・根拠・反対意見・未解決事項・判断材料に分解する。結論を押しつけず、読者が自分の判断を更新できることを目標にする。

最低限含めるもの：問い、前提、論点、根拠、反論または代替案、限界、次の判断。

### `source-explanation`

一次情報、公式記事、論文、仕様書などを、読者向けに再構成して説明する。原文の主張、追加した背景、自分の解釈、原文からは言えないことを区別する。

最低限含めるもの：元ソース、要約、背景、構造化した解説、解釈、限界、原文へのリンク。

### `analysis-report`

データや指標に基づいて、読者の判断を支援する。結論先出しにし、指標・分母・期間・比較基準を先に定義する。分析ロジックは適切なData Analytics Skillに委譲する。

最低限含めるもの：問い、結論、定義、根拠となる図表、セグメント解釈、限界、推奨、ソース情報。

### `comparison-decision`

候補を明示的な基準で比較し、状況ごとの推奨と、結論が変わる条件を示す。比較軸だけで結論を決めず、重み、前提、未評価項目を明記する。

最低限含めるもの：決定事項、候補、評価基準、比較表、トレードオフ、推奨、反証条件、次の行動。

### `tutorial-playbook`

読者が手順を実行し、期待結果を確認できる実践ガイドにする。説明よりも、前提・操作・結果・失敗時の分岐・検証を優先する。

最低限含めるもの：対象読者、前提、準備、手順、期待結果、失敗例、検証、完了条件。

`case-study` や `reference` が必要な場合は、まず上のモードのどれを主目的にするか決める。事例は `consideration` または `analysis-report`、用語集は `source-explanation` の配信形として扱い、モードを増やすのは繰り返し発生してからにする。

## 配信面

本文モードと配信面を混同しない。

| 配信面 | 用途 | 主な検証 |
| --- | --- | --- |
| `html-page` | GitHub Pagesの単一記事 | HTML意味構造、相対リンク、レスポンシブ、キーボード、ダークモード |
| `html-collection` | 複数ページのまとまり | 目次、ページ間リンク、一覧、前後移動、孤立ページ |
| `pdf-report` | 分析結果や比較結果の固定版 | PDFリンク、文字選択、図表、改ページ、出典 |
| `pdf-book` | 長編の章立て成果物 | 目次、章、脚注、参考文献、相互参照、組版、ページ単位の確認 |
| `epub-book` | Apple Books・Kindleなどで読むリフロー型電子書籍 | EPUBCheck、2階層以内の目次、本文・出典リンク、狭い画面と文字拡大への対応 |

`thinking` リポジトリの通常のHTML記事は `html-page` とし、複数ページ化はユーザーが求めた場合だけ選ぶ。PDF本のページ数は用紙、余白、本文サイズ、図表密度で変わるため、目次案にそれらを明記する。EPUB本は画面サイズ・端末・文字設定に応じて再配置されるため、ページ数ではなく文字数、読了時間、章節の構成で計画し、PDFとは別の成果物として検証する。
